# AE Browse：CEP 面板实现路径

日期：2026-10-14，香港时间。状态：阶段 0–2 的代码、开发构建和最小实机加载/登记/面板导入闭环已完成，见 [实机报告](CEP_LIVE_TEST_REPORT.md)。停靠/重开恢复、交互和性能条件继续逐项验收。构建见 [构建报告](CEP_BUILD_REPORT.md)，安装见 [安装说明](CEP_DEV_SETUP.md)。

## 1. 目标与技术选择

采用 **CEP 浏览界面 + Node 图形包服务 + 现有 JSX 执行层**。图形库保持独立文件夹，ZXP 用于发布和安装面板。

用户的主要流程是：选择图形库 → 浏览与搜索 → 查看预览 → 调整参数 → 添加到当前合成 → 更新或导出工具生成的实例。

这条路线优先改善素材浏览和操作体验。生成图层、修改属性和渲染仍受 AE 执行成本影响；ZXP 打包本身没有提速作用。

第一版以 Windows、本机 AE 26.0 为验证起点。实际 CEP、Chromium 和内置 Node 版本须在阶段 0 读取确认；其他 AE 版本及 macOS 后续单独验证。

## 3. 架构与数据流

```text
独立图形库：pack.json + assets/ + previews/ + resources/
                        │
                        ▼
CEP 内的 Node 服务：校验、登记、索引、缓存、用户预设
                        │
                        ▼
HTML/CSS/JS 面板：缩略图、搜索、详情、参数、提示
                        │
                        ▼
宿主桥：请求队列 + CSInterface.evalScript + 结果解析
                        │
                        ▼
JSX：重新检查目标 → 编译计划 → 执行 → 回读 → 返回结果
                        │
                        ▼
AE 当前合成中的工具实例
```

### 界面层

- 首版用轻量 HTML/CSS/JavaScript，先不引入大型框架和原生 Node 插件。
- 主区域采用缩略图网格；搜索、库选择和收藏入口保持固定，详情区显示参数、使用说明和依赖提示。
- 小宽度面板将详情区折叠或切换为单列；加载、空库、无搜索结果、缺失文件和未打开合成都有明确状态。
- 参数控件按清单声明生成，保留中文名称、单位、范围和帮助信息。
- 普通浏览、搜索和预制预览不调用 AE，不创建图层。

### Node 图形包服务

- 复用现有校验规则，集中处理登记、路径解析、索引、内容指纹和用户数据。
- 先通过 CEP 内置 Node 加载现有 CJS 模块；检查 `node:` 导入及所用 API，必要时在打包层做兼容处理。
- 首次登记进行完整校验；后续浏览使用索引，显式刷新及执行前重新检查相关数据。
- 源图形库只读取；索引、缓存、收藏和用户预设写入独立用户目录。
- 当前校验器大量使用同步文件调用。启用 Node 不等于界面自动获得后台线程，需要分块调度或另行验证工作线程方案。

### JSX 执行层

- 加载受控的 ES3 文件和 JSON 兼容实现，不依赖 AE-MCP 才能运行。
- 为现有适配器增加稳定入口，首版可直接执行已校验的清单片段和 JSON 描述。宿主仍检查结构、预算、参数和实际操作目标。
- 当前 `load` 的路径检查不能替代 Node 的完整真实路径与链接检查。正式入口应避免从未经确认的包路径再次读取数据；必须读文件时，执行前重新校验并核对实际读取内容。
- 不把包中字符串拼成脚本执行，不从图形包加载任意 JSX、JavaScript 或可执行文件。

Adobe 文档说明，CEP 可启用 Node，宿主操作通过 `evalScript` 进入 ExtendScript；这部分脚本仍在 AE 主线程运行。因此界面与文件服务应减少宿主调用，长任务需拆分。[CEP 官方文档](https://github.com/Adobe-CEP/CEP-Resources/blob/master/CEP_12.x/Documentation/CEP%2012%20HTML%20Extension%20Cookbook.md)

## 4. 宿主通信约定

采用固定分发函数和 JSON 请求，不为每个按钮拼接任意脚本。下面的名称是拟新增协议，不代表现有接口已经实现。

请求至少包含：`protocolVersion`、`requestId`、`operation`、`target`、`payload`。创建操作另有稳定的 `operationId`，用于重复请求识别；它与一次通信的 `requestId` 分开。

返回至少包含：`requestId`、`ok`、`data`、`diagnostics`、`timing`。错误以结构化代码和中文提示返回；桥接失败也转换成明确诊断。

| 拟新增操作 | 作用 | 宿主影响 |
| --- | --- | --- |
| `getHostInfo` | 读取版本、效果能力和桥接版本 | 只读 |
| `getContext` | 读取当前合成和选择目标 | 只读 |
| `instantiateAsset` | 包装 `create`，创建新实例 | 创建图层 |
| `readInstance` | 包装 `capture`，读取工具实例 | 只读 |
| `updateInstance` | 包装 `updateAppearance` | 修改受保护的外观属性 |
| `captureAsset` | 读取可导出的描述，由 Node 落盘 | 只读回读；随后写独立文件 |

- 每次只允许一个宿主请求执行；面板显示忙碌状态，防止重复点击创建。
- 请求字符串做 JSON 编码及脚本字符串转义，覆盖中文、引号、反斜杠、换行等情况。
- 返回 AE 对象的稳定标识和数据快照，不跨桥保存图层或属性对象。
- 点击导入时绑定合成；更新时绑定合成与实例身份。实际执行前再确认目标存在、身份匹配、未锁定，目标变化时停止并提示。
- 执行前核对包身份、版本、内容与参数。文件变动或包版本冲突时要求重新加载，不沿用旧预检结论。
- 超时只表示面板未收到结果，不能视为 AE 已停止。写请求超时后保持状态待确认；优先读取结果或实例状态，避免自动重试产生重复图层。
- 取消用于撤销未执行请求、停止扫描及后续批次。已经执行的单个宿主调用不能承诺立即中断。
- Undo 分组按一次用户操作组织，结束时可靠关闭；Undo 分组不等于事务回滚。

## 5. 分阶段交付

各阶段按依赖推进，先形成可运行构建，再安排对应测试。阶段完成以验收结果为准，不预先承诺开发天数。

### 阶段 0：验证 CEP 运行入口

**交付：** 最小面板、`CSXS/manifest.xml`、官方 `CSInterface.js`、JSX 加载器及 JSON 支持。

工作包括：读取实际 CEP/Node 版本；确认面板可打开、停靠及适应尺寸；启用 Node 并加载校验器；通过桥读取 AE 版本和当前合成；确认关闭重开后状态可恢复。开发期使用扩展目录，记录所需调试配置；正式版本通过签名包验证安装。

**验收：** 脱离 AE-MCP 正常加载；无合成时显示提示；中文 JSON 请求可往返；此阶段只读宿主，不创建或修改项目项。

### 阶段 1：图形库浏览

**交付：** “添加图形库”入口、持久登记、素材网格、名称与标签搜索、详情和错误提示。

用户选择含 `pack.json` 的目录。登记后复用 `inspectDirectory` 和 `planRegistration`，缺失预览使用占位图，单素材损坏只停用该项。首版分类取标签或已有命名空间元数据，不引入新必填字段。

索引先写临时文件，再在同一用户目录内提交替换；启动时能恢复或丢弃未完成写入。中文、空格路径及图形库移动后重新定位需要覆盖。移除登记只移除索引引用，不删除源目录。

**验收：** 能浏览示例包；错误素材不影响正常素材；重新打开面板保留登记；浏览期间 AE 项目无新增项；不向图形包写入用户配置。

### 阶段 2：导入最小闭环

**交付：** 圆角卡片参数区、“添加到当前合成”、状态与诊断提示。

复用现有参数计划和 `create`，执行前完成文件预检与实际宿主上下文检查。能力映射必须覆盖真实适配器；未知能力显示待检查或不支持，不能因类型名称存在就允许执行。

宽度、高度、圆角、颜色、动画类型与时长用于新建实例。已有基础效果按验证范围提供，可选效果缺失允许明确降级，必需效果失败阻止创建。一次操作完成后回读实例身份和关键属性；失败清理本次创建的图层。

**验收：** 从面板完成“加载库 → 调参数 → 导入 → 回读”；重复点击不创建重复实例；无合成、非法参数和缺失必需效果得到明确提示；已有合成和图层不被测试修改。

### 阶段 3：预览与交互完善

**交付：** 懒加载缩略图、选中素材的预制动画预览、收藏及近期使用、紧凑参数交互。

预览分成三类，界面明确标识：

1. **包内预制预览：** 首版优先使用，不驱动 AE；格式在实际 CEP 中确认可解码后选定。
2. **面板近似预览：** 圆角卡片可按参数绘制，但不承诺与 AE 色彩、效果和渲染逐像素一致。
3. **真实 AE 预览：** 后续提供显式入口，在独立临时合成渲染，结束后清理；不作为每次悬停的默认行为。

`preview` 的现有字段先核对协议与校验器支持，再实现图片或视频读取。新增预览格式通过明确的可选协议扩展接入，并保留旧包兼容性。

颜色控件提供预览色块；优先尝试接入 AE 原生选色交互，需单独验证调用方式、取消行为和选择恢复。无法稳定接入时先采用面板选色器，明确其实现状态。

**验收：** 滚动时仅加载可见及邻近素材的预览；隐藏或关闭面板暂停播放和释放资源；收藏引用稳定包/素材 ID；颜色确认与取消均正确，未经测试不声明原生交互已完成。

### 阶段 4：实例更新与导出

**交付：** “读取所选实例”“更新外观”“导出为图形包”，以及独立用户预设。

只允许更新身份确认的工具实例。保留已有动画；动画类型或时长变化继续提示当前更新入口不支持。锁定、手工修改、关键帧和表达式沿用现有保护规则。

首版滑块拖动只更新面板预览，松手或点击应用后提交 AE。实时更新作为可选增强，在节流、目标保护和回滚验证后加入，不在每个鼠标事件中写入宿主。

补齐整个更新过程的旧值与元数据恢复，覆盖写属性、回读和更新基线失败；不能只恢复部分外观数值就报告回滚成功。

导出先由 JSX 回读受支持数据，再由 Node 写独立暂存目录、执行完整包校验，最后提交到不存在的目标目录。现有 `exportPack` 的直接落盘流程只作为数据转换参考，不直接当成事务完成的正式导出服务。

导出当前单素材时，明确生成新包 ID 或作为新版本导出，避免沿用原库 ID/版本却改变内容。暂存、失败和已有目标都不覆盖原文件；预览、依赖和不支持内容须明确说明。

**验收：** 更新不改变图层身份和已有动画；失败可恢复并回读确认；导出包复制到新目录后可登记与重建；所有文件写入发生在用户选定的新目录或用户数据目录。

### 阶段 5：性能验收与 ZXP 发布

**交付：** 性能报告、可复现构建、签名 ZXP、安装及兼容性说明。

先测量并解决浏览和通信瓶颈，再签名打包。安装包包含界面、Node 服务、JSX、JSON 支持和必要本地依赖；运行不要求用户额外安装系统 Node 或启动 AE-MCP。测试样例、大量帧图和签名私钥不进入安装包。

ZXP 只发布工具。图形包、用户配置与缓存保持独立，面板升级不覆盖它们。签名凭据由发布环境提供，不写入源码；记录扩展 ID、版本、最低宿主范围、安装工具与失败诊断。

**验收：** 在关闭开发调试配置的环境中完成安装、打开、浏览和导入；升级后库登记和用户预设保留；记录实际验证过的 AE/CEP/Windows 版本。未测试的平台不宣称支持。

## 6. 性能策略与验收方式

优先让浏览不等待 AE，让宿主写入次数与用户操作次数相符。

- **索引与扫描：** 搜索读取轻量索引；完整扫描不在搜索或滚动事件中重跑。同步校验和哈希拆成有预算的小任务，文件读取按需进行。
- **列表与图片：** 虚拟化网格，仅保留可见范围及缓冲区；限制图片解码和读取并发；切库时取消旧任务，忽略过期结果。
- **动画预览：** 首版同时播放一个选中素材；离开详情、面板隐藏或关闭时停止。
- **缓存：** 用包/素材身份、内容指纹、预览类型和必要渲染参数作键；缓存可重建，提供大小上限与清理入口。未重新校验的缓存不作为执行许可。
- **参数交互：** 先更新本地视图再提交；宿主串行执行，合并尚未发送的同目标外观请求，创建和导出请求不合并。
- **宿主读取：** 启动和必要操作时读取能力；切回面板、显式刷新或执行前检查上下文，避免高频扫描整个项目。

以下数值是拟定验收目标，尚无实测结果。基准需记录机器、磁盘、AE/CEP 版本、素材数量、预览大小和冷/热缓存状态。

| 场景 | 暂定目标 | 测量边界 |
| --- | --- | --- |
| 1000 素材索引的搜索 | 结果更新 P95 ≤ 150 ms | 不含首次扫描；另报输入防抖延迟 |
| 1000 素材库的热缓存首屏 | 面板就绪后 ≤ 500 ms | 另报 CEP 冷启动与首次登记耗时 |
| 连续网格滚动 | 以约 60 fps 为目标，记录超过 50 ms 的界面任务 | 在实际 CEP 中测量，普通浏览器结果不替代 |
| 5000 素材库 | 保持可操作、可取消，不一次创建全部卡片节点 | 现有 5000 上限是协议预算，尚非性能认证 |
| AE 创建与更新 | 分别报告预检、桥接、宿主执行与回读耗时 | 先建立基线，不预设相对 JSX 的提速比例 |
| 连续使用和反复开关面板 | 资源释放后内存趋于稳定 | 纳入 CEP 相关进程，记录峰值和趋势 |

未达目标时按数据定位：磁盘读取、校验、哈希、DOM、图片解码、桥接或 AE 执行。通过减少预览并发、分批登记或关闭实时写入降级，并向用户显示清晰状态。

## 7. 拟新增目录

保留现有核心文件，面板与正式服务按职责新增。`cep/`、正式宿主入口、JSON 支持和 `build-cep.cjs` 已创建；缓存、正式 ZXP 发布脚本和签名包仍待后续阶段。

```text
cep/
  CSXS/manifest.xml
  index.html
  vendor/CSInterface.js
  ui/                    # 网格、搜索、详情、参数与状态
  node/                  # 索引、缓存、用户数据、文件服务
  bridge/                # 队列、JSON 协议、超时和结果处理
src/
  pack-validator.cjs     # 已有；保留 CLI 与 Node 测试入口
  native-shape-plan.jsxinc
  native-shape-adapter.jsxinc
  host-dispatch.jsxinc    # 拟新增正式宿主入口
  json-compat.jsxinc      # 拟新增 ES3 JSON 支持
scripts/
  build-cep.cjs           # 拟新增；生成扩展目录
  package-zxp.ps1        # 拟新增；签名发布
dist/                    # 构建产物，不手工维护
```

用户数据拟放在 `%APPDATA%/AE Browse/`，缓存拟放在 `%LOCALAPPDATA%/AE Browse/Cache/`。路径通过系统环境解析，并验证目录权限；库路径引用与内容文件分开保存。

## 8. 验证与项目保护

遵循项目 [AGENTS.md](../AGENTS.md)：每次测试前单独向用户说明范围与预期影响，明确是否进入真实 AE。Node 测试不自动调用宿主测试。

| 验证类别 | 范围 | 预期影响 |
| --- | --- | --- |
| Node / 包与预检 | 现有校验器、索引、协议编码、队列与导出失败处理 | 只在文件系统产生测试样例和报告，不进入 AE |
| CEP 加载与只读桥接 | 实际面板、内置 Node、加载器、版本和上下文 | 打开面板、读取宿主，不修改项目内容 |
| 实际 AE 属性测试 | 创建、外观更新、关键帧保护、回读与失败清理 | 仅操作明确标识的临时合成，可能影响 dirty 标志和撤销历史 |
| 渲染像素检查 | 临时合成中的真实帧及导出重建对照 | 产生临时项目项和帧文件，完成后清理 |
| 安装与性能检查 | ZXP 安装、升级、滚动、内存和冷启动 | 影响扩展安装或用户测试配置，执行前另行说明 |

宿主测试完成后删除本轮临时项目项，再扫描项目项确认不存在；不依赖删除后的 `itemByID`。报告保留运行标识、开始与结束时间、完成状态和清理结果，不保存或覆盖用户工程。

先运行与改动有关的 Node 验证，再单独安排实际 CEP、AE 属性和渲染检查。Node 通过、属性回读通过、像素一致分别报告；本次文档编写没有执行新测试。

## 9. 第一轮开发范围

下一轮从阶段 0 开始，第一轮以阶段 2 的最小闭环为目标：

- 一个可加载和停靠的 CEP 面板。
- 加载独立图形库，显示素材、参数与帮助。
- 当前圆角卡片的创建、错误提示和结果回读。
- 构建产物、运行说明及分层测试记录。

预制动画预览、收藏、原生选色、实例导出和 ZXP 发布按后续阶段推进。任意路径、多形状组合、预合成依赖收集、第三方效果特殊数据、自动在线更新和批量渲染留待相应适配器与需求明确后实现。
